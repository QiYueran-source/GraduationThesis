## 滚动窗口的agent决策 + 学习  
1. agent 设定：输入 (n,m,w) 三维张量，输出 (n+1) 维向量 action，其中 n 表示证券数量，该向量表示证券与现金的权重  
2.reward 设定，根据权重，计算证券组合的 (return, vol, sharpe, max_drawdown)，线性加权后得到 reward，用于强化学习更新模型  
3. 训练流程：  
    - 提前采样，采样若干大小为n的证券组合p，形成(p1,p2,p3 ... )  
    - 进入窗口win，遍历(p1,p2,p3 ... )   
        - 对于组合p，构建观测obs (n,m,w)，n为p中证券数量，m为回看期数，w为看到的因子数量(m,w决定了agent的数据能力)   
        - 调用agent的决策模型，model(obs) -> action  
        - 根据action，计算奖励reward  
        - 根据action和reward，强化学习模型model，得到model*，重复操作  
    - 滚动到下一个win，打乱(p1,p2 ...), 重复上述过程

## 遇到的问题  
1. 强化学习问题与可能解决方案：  
    - 训练问题：与机器人寻路等经典强化学习场景不同，agent学习本质上需要训练出一个因子交易员，能根据因子来执行交易，获取最大回报；因此，将每一次决策设定为一局游戏，而无需像寻路问题一样，需要多步后计算奖励和结果  
    - 标准化问题：reward涉及多个指标线性加权，因此需要对指标进行标准化，如果通过model实时计算出奖励，需要采用纵向标准化（以组合 p 的波动率 vol 为例，第 i 期计算出的 vol_i 需与 vol_{i-1}, vol_{i-2}, … 进行标准化，而不能使用 p1, p2, p3 的 vol_i 来标准化）   
    - SB3框架：比较复杂，最近在集中学习，尤其是涉及到自定义模型的问题  
2. AED 因子问题  
    - 设计输入时，使用通用的(n,m,w)形状的张量，可以设定 n=1，即为单证券问题，可方便地计算某一证券的 AED 因子，后续分析类似。如果使用n>1的数据，此时计算单个证券的 AED 因子就比较复杂，我认为可以用来做一些其他研究，如设定n=50，然后决策上证50组合之类的，暂未确定。
